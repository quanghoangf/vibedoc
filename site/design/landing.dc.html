Spec-driven development

Vibe coding forgets. Specs remember.

In a chat, what you asked for scrolls away and "done" means "trust me". VibeDoc keeps what each feature must do as living specs next to your code, turns the promises into tests, and checks the work against them before you approve it.

Without specs

✕ Intent lives in chat history and is gone next session

✕ The agent rebuilds how a feature works from old tasks

✕ "Done" is the agent's word for it

✕ Docs drift until nobody trusts them

With VibeDoc

✓ Each capability has one spec: requirements with WHEN/THEN scenarios

✓ The agent sees the related requirements when it claims a task

✓ Scenarios become the task's tests; done means they passed

✓ A finished epic merges its spec changes in one reviewed diff

Accept

Brownfield-first: you never write specs for the whole codebase up front. A spec starts with the first epic that touches a feature and grows with every epic after it, the same delta idea OpenSpec uses (ADDED, MODIFIED, REMOVED, RENAMED).

Plan. Build. Prove. Review.
Four commands, one loop.

The commands ship as a Claude Code plugin. In Cursor or any other MCP client, the same steps are the vibedoc_* tools.

01

Plan

Turn your docs and a short interview into horizons and epics with scenarios.

/vibedoc:roadmap

02

Break down

Split an epic into tasks an agent can pick up cold, each seeded with its scenarios.

/vibedoc:breakdown R004

03

Build and prove

Claim, build, test and commit, task by task. Each one ends with its evidence.

/vibedoc:work R004

04

Review

Approve on the proof, or send findings back. Not sure what's next? Ask.

/vibedoc:next

Inside VibeDoc

One local app for the whole loop.

A board your agent moves

Tasks are markdown files. Agents claim, move and finish them over MCP, and each card shows its test results and who is on it.

A roadmap that tracks itself

Horizons and epics on a map or a timeline. Progress, at-risk epics, unmerged spec changes and uncovered scenarios come from the tasks.

Evidence for every task

Each checklist item runs as a Playwright step. Review the screenshots and video, flag a doubt, approve or send back.

Scenarios as acceptance tests

Each epic lists its WHEN/THEN scenarios and shows which ones are passed, failed or still unproven by its tasks.

Living capability specs

One spec per feature, edited like any doc. Agents get the related requirements whenever they open a task in that area.

Memory between sessions

A handoff plus one-fact knowledge entries the next agent reads first, with history you can restore.

Every link, on one map

Docs, tasks, epics, specs and entries, joined by the links in their text. Broken and stale links stand out.

Running in a minute.

Local-first: one process on your machine, no account, no database. Your plans stay plain markdown in your repo.

1 · Start VibeDoc in your project

cd your-project
npx vibedoc

"vibedoc": {
